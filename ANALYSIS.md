# Анализ ConfigurationUSARTn

Документ фиксирует замечания по исходным файлам `ConfigurationUSARTn.c` и `ConfigurationUSARTn.h`.

## Подтверждённые по исходникам исправления

### Неверный IRQ для USART0 в GD32F303_

В `ConfigUsartDMA_Rx()` для `USART0` использовался `USART1_IRQn`. Для USART0 должен использоваться `USART0_IRQn`.

Исправление относится к ветке `GD32F303_`, к обработке параметра `iRQn_receiv_Uart`.

### Дублирующий вызов `usart_enable()` в GD32F303_

В `ConfigUsart()` USART включался дважды. Второй вызов после `nvic_irq_enable()` был удалён как дублирующий. Остальной порядок настройки не менялся.

### Ошибка в примере GD32F450_

В примере `ConfigUsartDMA_Rx()` использовался флаг `iRQn_full_transmit_Dma`. Для функции приёма должен использоваться `iRQn_full_receiv_Dma`.

## Участки, требующие проверки

### DMA и IRQ

Соответствие USART, DMA-канала, субпериферии и IRQ нельзя окончательно подтвердить только по исходнику. Нужно сверить таблицы с reference manual конкретной ревизии GD32 и заголовочными файлами используемого SDK.

Также необходимо проверить соответствие выбранных GPIO схеме конкретной платы.

### Тип буфера GD32F303_

В API GD32F303 буфер объявлен как `uint32_t*`, а ширина DMA установлена в 8 бит. Это не объявляется подтверждённой ошибкой без проверки вызывающего кода и SDK. Перед изменением типа нужно проверить все места вызова и фактический тип буферов.

### Обработчики прерываний

В библиотеке объявлены обработчики USART и DMA, но логика обработки должна находиться в проекте пользователя. Нельзя добавлять универсальный обработчик без знания протокола, буферов и платы.

При включении прерывания проект должен определить соответствующую функцию, проверить источник прерывания и очистить нужные флаги согласно документации SDK. Для IDLE-прерывания может потребоваться порядок чтения регистра данных и очистки флага, установленный для конкретного SDK.

### Циклический DMA

При `circulationEnable = 1` проект должен самостоятельно определить, как отслеживать новые данные, границы пакета и переполнение буфера. Универсальное решение зависит от протокола обмена.

## Ограничения анализа

Сборка и аппаратное тестирование не выполнялись: в репозитории нет проекта, конфигурации компилятора, SDK и описания конкретной платы. Поэтому аппаратные соответствия должны быть проверены отдельно.
